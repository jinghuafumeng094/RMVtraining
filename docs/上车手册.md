## 1. 构建

```bash
cd ~/workplace/rm_autoaim
cmake -S . -B build -DCMAKE_CXX_FLAGS=-O2
cmake --build build -j"$(nproc)"
```

产物 `build/rmv_training`，上车跑的就是它。

### 两个不许动的地方

**不要用 `-DCMAKE_BUILD_TYPE=Release`。** Release 会加 `-DNDEBUG`，把 `tests/` 里两百多处裸 `assert` 全部编译掉，`ctest` 照样报 7/7 但是假绿。要优化就加 `-DCMAKE_CXX_FLAGS=-O2`，`CMAKE_BUILD_TYPE` 保持不设。

**不要给 `CMakeLists.txt` 的 `CMAKE_BUILD_TYPE` 补默认值。** 现在它没有默认值，所以默认不带 `-DNDEBUG`，断言是活的。补上默认值会让评分方跑出假绿的 `ctest`。

### 依赖

缺哪个 `cmake` 会直接报出来：

- Eigen3
- OpenCV 4，只要 `core imgproc calib3d objdetect ml imgcodecs` 六个模块。全仓没有 `videoio` 符号，取流走 MVS SDK
- 海康 MVS SDK，默认找 `/opt/MVS`。装在别处用 `-DMVS_ROOT=<安装根目录>`

MVS 库目录已经烤进可执行文件的 rpath，所以**不用 source 任何 `MVCAM_*` 环境变量**，干净终端直接跑。

### Web Debug 是默认开的

`ENABLE_WEB_DEBUG` 默认 `ON`。`web_debug` 这个 CMake 目标用 `PUBLIC` 带上 `WEB_DEBUG` 宏，`rmv_training` 链了它就有 HTTP 服务，**不需要额外加编译选项**。

真把它关掉的话，`WEB_LOG` 会变成空宏：程序照常跑、检测照常做，但页面上一条数据都没有。所以「页面是空的」先查这个开关，不用怀疑代码。

## 2. 运行

```bash
./build/rmv_training <串口设备> <波特率> <相机标定文件> [Web端口]

# 例
./build/rmv_training /dev/ttyACM0 115200 config/camera.yaml 8080
```

Web 端口默认 8080，省略就是它。

### 找串口设备

```bash
ls /dev/ttyACM* /dev/ttyUSB*
dmesg | tail -20          # 插上主控板后看新冒出来的是哪个
```

海康相机不算在内：U3V 相机既不走 `/dev/tty*` 也不走 `/dev/video*`。

### 启动的前提条件

程序在 `main` 里按顺序校验，任一步失败就直接退出：

1. 相机标定文件读得动（`config/camera.yaml`）
2. 串口打得开（设备名对、有权限）
3. 串口参数配得上（115200 8N1）

过了这三关就起服务。之后主循环里还需要**串口持续送来有效帧**才会往下走到检测：帧太旧、`status` 不是自瞄状态、姿态量非有限，都会直接回一个安全帧，不进算法。

相机是后一步才用的：`get_pic` 连续失败 3 次，操作线程会退出、整个程序结束。所以**没有相机就只能跑到服务起来的瞬间**，看不到曲线 —— 宿舍里看页面请用第 0 节的 `web_debug_replay`。

### 看数据

```bash
xdg-open http://127.0.0.1:8080
curl http://127.0.0.1:8080/health     # 返回 OK 就是活着
```

车在别的机器上，从自己电脑转发过去：

```bash
ssh -L 8080:127.0.0.1:8080 <用户名>@<车上那台机器>
# 浏览器还是开 http://127.0.0.1:8080
```

### 页面三个坑

1. **历史只有约 2 秒。** 环形缓冲是 10000 条样本，按条数不按帧数算；满帧打约 29 条、165 fps，铺满就这么多。顺序必须是**先开浏览器，再让车动** —— 反过来回头再开，只剩最后 2 秒。
2. **别刷新页面。** 浏览器自己那份曲线在内存里，一刷新就丢，重连只从环形缓冲那 2 秒开始发。一直开着别关。
3. **程序一退，服务就关**，页面随即断开。

真嫌短，两个办法：调大 `web_debug/include/WebLogger.hpp` 的 `kBufferCapacity`，或者降低打点密度。

### 相机参数由程序自己复位

`student/src/HikCamera.cpp` 每次开盘都写死：

```
ExposureAuto = 0        ExposureTime = 5000 us
GainAuto     = 0        Gain         = 0 dB
BalanceWhiteAuto = 0
```

所以相机被别的程序动过也没关系，本程序一开就复位。**但顺序不能反**：先关自动再写值，自动还开着的时候写曝光会被立刻盖回去，还不报错。

反过来注意：如果你在用 MVS 客户端或 `params.py` 调相机，跑完要写回 5000 us / 0 dB / 三个 auto 全 Off，否则那段时间的图是坏的。

### 红蓝队

敌方颜色由串口下发的 `status` 决定（`enemyColorFromStatus`），不是程序参数，也不用改配置。想看另一种颜色，让电控切。

## 3. 看哪些量

页面上共 36 个键。按用途分六组。

### 第一组：检出与 PnP（先确认输入是对的）

| 键 | 看什么 |
|---|---|
| `armor_count` | 本帧检到几块。**跟踪状态下的常态是 1 块**，两块只在换板瞬间出现 |
| `detection_id` | 编号。哨兵板上是哨兵图标，出 7 是对的；出 0 表示判定成"非 1-8 的贴纸"，代码里整条不画框 |
| `detection_confidence` | 分类置信度 |
| `pnp_reprojection_error` | 重投影误差，正常 0.7 到 0.8 px，超过 5 px 被位姿解算拒掉 |
| `pnp_distance_m` | 单帧原始测距，未滤波 |
| `pnp_yaw_rad` / `pnp_pitch_rad` | 单帧原始角度，未滤波 |
| `target_x_px` / `target_y_px` | 目标像素坐标 |
| `camera_fps` | 正常 165 左右 |
| `empty_frame` | 空帧累计计数 |
| `process_time_ms` | 单帧处理耗时 |

这一组是全链路里**唯一能直接看见观测值**的地方。后面 EKF 出问题，先用它排除"输入本来就是坏的"。

### 第二组：EKF 状态（判断滤波对不对）

| 键 | 看什么 |
|---|---|
| `ekf_state` | 0 无目标 / 1 Stable / 2 Unstable。**这就是 `crc`**，直接对应通信字段 |
| `ekf_x_m` `ekf_y_m` `ekf_z_m` | 旋转中心位置，世界系 x 前 / y 左 / z 上，原点在云台旋转轴 |
| `ekf_vx_m_s` `ekf_vy_m_s` `ekf_vz_m_s` | 中心速度 |
| `ekf_yaw_rad` | 车体朝向 |
| `ekf_yaw_rate_rad_s` | 车体角速度 |
| `ekf_radius_1_m` `ekf_radius_2_m` | 两组半径，按板槽位奇偶分开 |

`ekf_z_m` 有个注意点，见第 5 节第 0 步。

### 第三组：状态机（判断为什么进不了 Stable）

| 键 | 看什么 |
|---|---|
| `ekf_streak` | 带符号：正数是连续命中帧数，负数是连续丢失帧数。换板和遮挡时它跳 |
| `ekf_aim_index` | 当前瞄哪块板，0 到 3 |
| `ekf_rejected_count` | 被闸门拒掉的观测累计数。它一直涨说明观测在批量被拒 |

### 第四组：输出与指令（判断打不打得到）

| 键 | 看什么 |
|---|---|
| `target_id` | 目标编号 |
| `target_yaw` `target_pitch` | 下发给云台的绝对角。`target_yaw` 是绝对方位角；`target_pitch` 是**弹道发射仰角**，含下坠补偿，比瞄准点的几何仰角高一点（5 m 处约 2.4°） |
| `target_distance_m` | 到瞄准点的距离 |

`crc != 1` 时 `fire_allowed` 恒假，这是代码里的硬约束，页面上表现为开火位不抬。

### 第五组：派生角（自查用）

这三个角不参与控制，也不回流进滤波器。它们是把已经估出来的状态按几何关系拼出来的，车体匀速自转时每一个都有一条**事先算得出来的波形**，形状、周期、幅值都能对。对不上就说明对应的那路状态没收敛，或者模型写错了。

两张图配着看：`docs/img/派生角波形.png` 是**理论形状**，纵轴标了刻度、周期标了秒数、幅值上限也画出来了，判"对不对"以它为准；`docs/img/派生角三例.png` 是**本机回放实测**，形状一样但页面不给刻度和理论线，只用来确认"车上能出这条曲线"。

约定：槽位 `i` 的板方位是 `body_yaw + i * 90 度`，半径按奇偶取 `radius_1_m` / `radius_2_m`。三个角只记 0 号槽位，另外三块板的同一个角只差 90 度的固定相位，形状完全一样。

| 键 | 顶点 | 定义 | 波形 | 周期 | 对不上说明什么 |
|---|---|---|---|---|---|
| `ekf_plate_me_angle_rad` | 敌车旋转中心 | 0 号槽位板与我方云台原点之间的无符号夹角 | 三角波，0 匀速涨到 pi 再匀速折回 | `2 pi / omega` | 斜坡速率对不上 `ekf_yaw_rate_rad_s`，就是 `ekf_yaw_rad` 没收敛；同一条上不同段的速率差得多，看 `ekf_x_m` `ekf_y_m` |
| `ekf_slot_phase_rad` | 无 | `body_yaw` 折到八分之一圈，取值 0 到 pi/4 | 三角波，周期是上一条的四分之一 | `pi / (2 omega)` | 它只由 `ekf_yaw_rad` 决定，与位置和距离无关。**这条干净而上面那条毛，问题在中心；两条一起毛，问题在 yaw** |
| `ekf_plate0_parallax_rad` | 我方云台 | 0 号槽位板的方位角减去车心的方位角 | 绕 0 振荡的正弦 | `2 pi / omega` | 幅值约 `asin(radius_1_m / 距离)`，幅值偏大说明半径估大了；整条慢慢偏离 0 说明中心估偏了 |

这三条的价值在于**一屏之内把 `x y z`、`yaw`、`radius` 三路状态分开定位**：中心的病只脏第一条，yaw 的病脏前两条，半径的病只脏第三条。不用等 NIS 补出来。

`docs/img/派生角波形.png` 的画图假设：车心静止在距我 5.0 m 处、以 `omega = 2.0 rad/s` 匀速自转，`radius_1_m = 0.25 m`，云台不转。这三个数只影响周期秒数和幅值大小，不影响形状：换一个 `omega`，横轴按比例伸缩而三条的相对疏密不变；换一个距离，只改第三条正弦的幅值。所以现场拿它比的是**形状和相对周期**，第一条的周期正好是第二条的四倍，这一条与所有参数无关，是最硬的判据。图上另外各画了一条灰色虚线做反例：第一条的平线对应"编号跟着瞄点走"，第三条的二倍幅值曲线对应"半径估大一倍"。这张图由 `rm_autoaim_testrig/gen_derived_angles_svg.py` 生成，改图改脚本再重跑，别手改 SVG。

**回放工具里看不到完整的三角波**：`web_debug_replay` 每轮都超时重置一次，滤波器重新初始化时 `body_yaw` 被置成车心指向云台的方向，所以 `ekf_plate_me_angle_rad` 每轮都从 0 重新起步，大约 1.6 秒就被打断。车上目标连续可见时才是完整周期。

### 第六组：不过滤波器的参照（判断是跟不上还是模型有偏）

上面五组的曲线全部出自 EKF 自己，它自己算、自己报。滤波器错了但错得前后一致的时候，页面上看不出来，它不会跟自己打架。这三个键只用相机侧的原始量做差，不经过滤波器，专门拿来和 `ekf_yaw_rate_rad_s` 对照。

| 键 | 看什么 |
|---|---|
| `gimbal_yaw` | 云台角。下面第二条单独看没有意义，云台一转它就动，要跟这一条一起看 |
| `armor_orientation_yaw` | 装甲板背向在云台系里的方位角，右正，板正对镜头时为 0。**原样输出，不经过任何闸门**，所以换板那一帧会看到 90 度跳变，这是对的，不是坏数据 |
| `ekf_meas_yaw_rate_rad_s` | 相机量出来的车体角速度，rad/s，左正，与 `ekf_yaw_rate_rad_s` 同向同量纲 |

口径是：云台系里的板背方位角加回云台角就是板在世界系里的方位角，它的下降速率就是车体自转速率。
```
theta_world = armor_orientation_yaw + gimbal_yaw
omega_car   = -d(theta_world)/dt
```
两个偏航角的符号约定是反的（`gimbal_yaw` 右正、EKF 的车体 yaw 左正），加回世界系之后自然消掉。

**两条角速度贴在一起，说明滤波器跟得上相机；分叉，说明它更信自己的模型。** 这两种病的方向是反的：跟不上是过程噪声给小了，对应 `angular_accel_noise_rad_s2`（转得快慢）和 `accel_noise_m_s2`（平移快慢）；模型有偏是观测噪声给错了，对应 `lateral_noise_scale` / `depth_noise_scale` 那四个。**先看分不分叉再决定拧哪一边**，别不分青红皂白一起调。

跳变闸门取 45 度。165 fps 下真运动每帧只走零点几度，离 45 度差两个数量级，误伤不到；换板的 90 度必被挡住。挡不住的是平板 PnP 双解翻转带来的约 1.2 度跳变，单帧会蹦出约 3.5 rad/s 的假尖刺。真嫌毛就把 `MeasYawRate::Config::smoothing_alpha` 从 1.0 调小，时间常数约 `1 / (alpha * 帧率)` 秒。

## 4. 动手调参之前：把 NIS 补出来

### NIS 是什么

新息是 `r = z - h(x⁻)`，即这次量到的板心三维坐标减去按当前状态预测出来的板心三维坐标。它没法直接判"离谱不离谱"：远处 1 米正常，近处 1 厘米可能就是错的。所以除掉不确定度：

```
S   = H P⁻ Hᵀ + R        （3x3，新息协方差）
NIS = rᵀ S⁻¹ r            （标量，无量纲）
```

模型自洽时 NIS 服从三自由度卡方分布，**均值就是 3**。

代码里它有两个用处：

| 位置 | 门槛 | 作用 |
|---|---|---|
| `ArmorEkf.cpp:463` | `best_nis > 11.34` | 统计闸，整帧拒掉这次观测 |
| `ArmorEkf.cpp:527` | 最近 5 次均值 < 8.0 | 进入 Stable 的条件之一 |

它同时是调 R 的标尺：均值约 3 说明 R 量级对；远大于 3 说明 R 填小了，真观测被当成异常值批量拒掉；远小于 3 说明 R 填大了，观测权重被压低，收敛慢、跟踪滞后。

### 为什么必须补

`ekf_state` 卡在 2 有两条完全不同的路：

- 协方差三道门没过（车还没转够，滤波器还不够确定）—— 要等，不该动参数
- NIS 均值门没过（观测正在被判成离谱）—— 要动 R 或 Q

**这两条的修法正好相反**，而 NIS 是唯一能区分的量。它现在是 private，没有公开访问器，`main.cpp` 里也没有这个键，现场只能瞎猜。

### 三处改动

1. `PredictionResult` 加一个 `float nis_mean` 字段
2. `ArmorEkf` 加一个公开的 `nisMean()` 访问器，`buildPrediction` 里填进结果
3. `main.cpp` 的 `logPrediction` 加一行 `WEB_LOG("ekf_nis_mean", ...)`

补的时候注意一点：`recordNis()` 在闸门之后（`ArmorEkf.cpp:485`），**被拒的帧不进均值**。所以均值低不等于模型自洽，可能是大部分帧都被拒了、只有少数干净帧进了统计。它必须和 `ekf_rejected_count` 一起看才成立。

## 5. 调什么、怎么调

### 参数在哪儿，怎么改

全部在 `student/include/ArmorEkf.hpp` 的 `Config` 结构里，是**编译期默认值**，没有运行期配置文件。

也就是说：**调参等于改源码加重编。**

实测代价（本机 24 核，`-DCMAKE_CXX_FLAGS=-O2`）：碰一下 `ArmorEkf.hpp`，只有三个编译单元会重编（`StudentTasks.cpp`、`ArmorEkf.cpp`、`tests/test_ekf_predict.cpp`），**约 4 秒**。加上重启程序和重新等收敛，一轮大约十几秒。

所以「一次只动一个参数」这条纪律的理由是**归因**，不是时间：同时改两个数，等结果变好了你不知道是谁的功劳。时间上不必太吝惜，想试就试。

### 三类参数，只有第三类能动

| 类别 | 具体 | 动不动 |
|---|---|---|
| 必须按车型填对的 | `plate_count` `plate_spacing_rad` `initial_radius_m` `plate_height_m` | 上车前就填对。填错不报错，只会把误差算进别的状态里 |
| 已经量过的，别动 | `jump_gate_m` 0.6、`nis_gate` 11.34、`max_reprojection_error_px` 5.0、`radius_drift_m`、`radius_variance_floor_m2` | 前三个离线实测余量 6.4 倍。后两个是半径随机游走，半径收敛慢是几何问题不是调参问题，放宽只会让半径乱飘 |
| 真正能调的 | R 四个系数、Q 两个、Stable 三道门、Stable 三个时序、开火三个容差 | 就调这些 |

### 第 0 步：核对读数，先别调

车停住、云台俯仰归零。等 `ekf_state` 稳成 1，看 `ekf_z_m` 对不对得上**板心高度**。

注意它报的是板心高度，不是旋转中心高度：`plate_height_m` 默认全零，滤波器会把当前看得见那块板的真实高度整个吃进 `pz`，两者差一个板高差。

绝对值里还混着外参 `translation_camera_to_gimbal` 的 z（51.5 mm）和相机安装误差，都是常数偏置，会被 `pz` 一起吸收。所以：

- 绝对值差两三公分以内，不用追，也追不出是谁的错
- **能核的是变化量**：车原地转、云台俯仰不动，换板那一瞬间 `ekf_z_m` 跳的台阶应该等于两块板的真实高差。哨兵相对两块等高，正对换到背对，台阶应该是 0

`plate_height_m` 填不填**不影响瞄准**：`h_i` 与 `pz` 只出现在同一个方程里，滤波器会把当前看得见那块板的真实高度整个吃进 `pz`，瞄准点的竖直坐标照样对。要填的话按 `{h0, h1, h0, h1}` 的结构，和两组半径的奇偶配对一致，收益只在 `center_z_m` 这个上报量上。

### 看波形：形状判方向，NIS 判是哪一头

上面几步都是按单个读数判。曲线还能多给一样东西：**形状**。有两个边界先记住。

**一、页面上没有真值线。** 唯一能对照的是 `pnp_*` 那一组单帧观测，而它自己就带噪。所以波形只能判"跟得紧还是跟得松""有没有来回摆"，判不了绝对准不准：一条平滑的曲线可以是平滑地错着。

**二、同一个形状常对应两种相反的病因。** 输出抖动，**Q 调大和 R 调小都会让增益 `K` 变大**，波形长得一样。分开它们要看 NIS 均值往哪边偏，两个病因把它往相反方向推。方向是从第 4 节那条 `S = H P⁻ Hᵀ + R` 直接读出来的：`R` 变小则 `S` 变小则 NIS 变大：

| 形状 | R 那一头 | Q 那一头 |
|---|---|---|
| 跟得太紧，观测毛刺穿到输出 | `R` 小，NIS 高 | `Q` 大，NIS 低 |
| 跟得太松，换向时明显落后 | `R` 大，NIS 低 | `Q` 小，NIS 高 |

**波形定"太紧还是太松"，NIS 定"是 Q 那一头还是 R 那一头"。这就是第 4 节必须先做的理由** —— 没有 NIS，这两行每一格都只剩"二者之一"。

对着看两条曲线的方式：页面**每张图只画一个键，不能叠加**，右上角的 CSV 按钮导出单键历史，两张 CSV 到外面画到一起。想慢慢看形状用第 0 节的回放工具，浏览器每个键留约 30 秒。

还有一处别混：`pnp_yaw_rad` / `pnp_pitch_rad` 是**相对当前云台**的角度，`target_yaw` / `target_pitch` 是绝对角，**差一个 `gimbal.yaw`**。比形状可以，别比绝对值。

上面这张表里的曲线形状都是"出问题长什么样"，得先知道"正常该长什么样"才判得出来。第 3 节第五组那三个派生角就是为这件事加的：它们的正常波形能事先算出来，形状、周期、幅值都有数，对不上直接回头查对应的那路状态。理论形状和刻度见 `docs/img/派生角波形.png`，本机回放实测见 `docs/img/派生角三例.png`。

| 形状 | 说明什么 | 改哪个参数，往哪改 |
|---|---|---|
| `ekf_state` 在 1 和 2 之间跳方波 | 滞回不够 | `stable_hold_misses` 调大，或 `recover_frames` 调小 |
| `ekf_streak` 走锯齿，涨几帧又掉回负 | 观测一轮一轮被拒 | 回第 1 步，先看 NIS 均值 |
| `ekf_z_m` 单帧跳一个台阶 | 换板本身正常，不用改 | 连着几帧乱跳、跳完回不来：平板 PnP 双解跳支，回位姿解算 |
| 慢转时中心读数稳定偏着，车一转快偏差就没了 | 几何残差，不是噪声没调好 | 停下调参。离线合成夹具在 0.4 rad/s 下量到中心偏 0.052 m、两个半径收成 0.309 / 0.177 对真值 0.28 / 0.22，转速提到 2.0 rad/s 就收敛到 0.0000（`docs/答辩-EKF跟踪与预测.md` 1131 行） |
| `ekf_x_m` / `ekf_y_m` 单调爬走，越漂越远 | 不是噪声问题 | 停下调参，回位姿解算查 `h` 和单位 |

### 第 1 步：调 R（观测噪声）

四个系数：

```
lateral_noise_scale     0.002     横向
lateral_noise_base_m    0.005     横向
depth_noise_scale       0.010     沿视线方向
depth_noise_base_m      0.010     沿视线方向
```

横向两个管板心在垂直于视线方向上的两个分量，深度两个管沿视线那个分量。观测噪声按 `sigma = scale * 距离 + base` 随距离变。

**标尺是 NIS 均值**（所以第 4 节必须先做）：均值落到 2 到 4 之间就算匹配。

一次性四个一起动会不知道是谁起作用。建议先横向后深度，每次只倍率化一组。

### 第 2 步：调 Q 的平移项

```
accel_noise_m_s2    6.0
```

做法：用手在镜头前挡 0.2 秒再拿开，看两件事，`ekf_state` 几帧回到 1、`ekf_streak` 从负数回升多快。

- 调大：恢复快，稳态抖
- 调小：平滑，恢复迟钝

取「0.2 秒遮挡后 K 帧内恢复」的拐点。这是旋转车体的平移机动性，跟车能多快变向有关。

### 第 3 步：调 Q 的转动项

```
angular_accel_noise_rad_s2    12.0
```

让车原地转。这一项和 `stable_yaw_std_rad` 是同一件事的两端：噪声给大，yaw 的协方差涨得快、同时又更容易超过门槛。

已知的两个结论，先知道能省一轮：

- 慢转但确实在转（`ω > 0`）进不了 Stable，是**调参问题**。这个平台的协方差按 `√α` 缩放，`α` 取 1 时 `ω = 0.3 rad/s` 也能进 Stable
- 完全不转进不了 Stable，是**几何问题**。把 `α` 降 100 倍，yaw 标准差反而略大且单调涨，调它没用

门槛大约挂在 `ω ≈ 0.8 rad/s`。

### 第 4 步：最后动 Stable 三闸和开火容差

```
stable_center_std_m     0.10     位置标准差上限
stable_radius_std_m     0.05     半径标准差上限
stable_yaw_std_rad      0.10     yaw 标准差上限

stable_frames           15       首次进 Stable 要的连续命中帧数
recover_frames          10       丢失后回 Stable 要的连续命中帧数
stable_hold_misses       3       丢这么多帧以内仍维持 Stable

fire_yaw_tolerance_rad   0.02
fire_pitch_tolerance_rad 0.02
fire_spin_tolerance_rad_s 1.0
```

**前面三步没调好就别碰这三个门。** 在这时放宽门槛等于把问题盖住：`ekf_state` 会变绿，但状态本身还是没收敛，答辩一问就露。

`fire_spin_tolerance_rad_s` 要注意它的含义：目标是别在高速自转时开火。设太大等于没有这道门。

`fire_pitch_tolerance_rad` 比的是 **`target_pitch` 与当前云台绝对仰角之差**，也就是"指令到位了没有"。因为 `target_pitch` 是含下坠补偿的弹道发射角，这个门顺势也把补偿量纳进来了。放它之前想清楚：它是"允许云台偏离指令多少度就开火"，不是"允许偏离瞄准点多少度"。

### 现场场景对到参数

这张表按单个读数判。曲线的形状另有一套读法，见前面的「看波形」一节。

| 现象 | 先确认什么 | 改哪个参数，往哪改 |
|---|---|---|
| `ekf_rejected_count` 一直在涨，`ekf_streak` 频繁归零 | 补上 NIS 后看均值 | **NIS 均值 > 4**：R 填小了。先动横向的 `lateral_noise_scale` 与 `lateral_noise_base_m`，**乘 1.5 到 2 倍**；不够再动深度的 `depth_noise_scale` 与 `depth_noise_base_m`。**NIS 正常**：不是 R 的问题，看下两行 |
| 一直停在 `ekf_state = 2`，但观测没被拒、`ekf_streak` 是正的 | 慢转还是完全不转 | **慢转（`ω > 0`）**：`angular_accel_noise_rad_s2` **调小**，它和 `stable_yaw_std_rad` 是同一件事的两端。**完全不转**：几何问题，调它没用 |
| 同上，且卡的是位置那一路 | 进 Stable 前 `ekf_x_m` / `ekf_y_m` 还在飘 | `accel_noise_m_s2` **调小**（6.0 → 3.0） |
| 收敛慢，车都转半圈了还没稳 | 慢的是位置还是 yaw | 位置：`accel_noise_m_s2` **调大**。yaw：`angular_accel_noise_rad_s2` **调大** |
| 稳住了但读数抖 | 抖的是位置还是 yaw | 位置：`accel_noise_m_s2` **调小**。yaw：`angular_accel_noise_rad_s2` **调小** |
| 挡住 0.2 秒就掉出 Stable | `ekf_streak` 归零后 `ekf_state` 多快变 2 | `stable_hold_misses` **调大**（3 → 5）：允许更多帧纯预测 |
| 观测回来了却要等很久才回 Stable | `ekf_streak` 从负爬到 `stable_frames` 要多久 | `recover_frames` **调小**（10 → 5）；若 `ekf_streak` 爬起来本身就慢，那是观测在被拒，回第一行 |
| 丢一次直接回 `ekf_state = 0` | 丢失时长是不是真超过 1.5 秒 | 真超过就别动 `reset_timeout_s`，那是正确定义。没超过说明观测在被拒，回第一行 |
| 换板瞬间 `target_yaw` 跳一下 | 跳的幅度 vs `aim_switch_margin_rad` | `aim_switch_margin_rad` **调大**（5 度 → 8 度）。换板在数学上不该让 `target_*` 跳，先确认不是观测被拒造成的 |
| `ekf_z_m` 换板时跳一个台阶 | 台阶是不是对应两块板的真实高差 | **正常，不用改。** 它吸收了当前可见板的板高；只有两块板同框那几帧才与 `plate_height_m` 有关 |
| 云台对齐了但 `fire_allowed` 不给 | 看 `target_yaw`、`target_pitch`、`ekf_yaw_rate_rad_s` 各差多少 | 方位差大：`fire_yaw_tolerance_rad`。仰角差大：`fire_pitch_tolerance_rad`（比的是"指令到位没有"，含下坠补偿）。自转没停：`fire_spin_tolerance_rad_s` |
| 远处测距乱跳 | `pnp_distance_m`、`pnp_reprojection_error` | 不动 EKF，回位姿解算 |
| `armor_count` 老是 0 | `detection_id`、`detection_confidence` | 不动 EKF，回检测或颜色阈值 |

**第二、三行是这张表里最难判的两行**，因为进 Stable 的三道协方差门读的是 `P` 的对角线，而 `P` 在 Web Debug 上看不见。现场只能靠"慢转还是完全不转""位置飘还是 yaw 飘"这种物理现象反推。**要判得干脆，就顺手加两三个 `P` 对角线的键**（`sqrt(P(Px,Px)+P(Py,Py))`、`sqrt(P(Yaw,Yaw))`、`sqrt(P(R1,R1)+P(R2,R2))`），和加 NIS 键是同一处改动。

**放宽门槛是最后一步。** 前三步（R、Q 平移、Q 转动）没调好就碰 Stable 三闸和开火容差，等于把问题盖住：`ekf_state` 会变绿，状态本身还是没收敛。


### 三条纪律

1. **一次只动一个参数。** 一轮十几秒，但两个一起动就分不清是谁的功劳
2. **先插电。** 不插电主频会掉一半，同一批数据跨轮比绝对值没有意义。出数之前先确认插着电
3. **单次异常值不许升级成规律。** 看到一个不正常的数，先问「有没有不需要异常就能解释的说法」，再决定要不要当线索
