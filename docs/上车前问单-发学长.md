## 第 1 组：必须先落定

### 1.5 `gimbal.yaw` 取正的方向（pitch 那半已答，只剩这一半）

**问**：电控下发的 `gimbal.yaw`，取正是**右转**还是**左转**？

**当前默认**：**右正**。我们内部的量取的是另一套，说明一下免得对不上：世界系是「前 x / 左 y / 上 z」，所以从正前方往左转，数学上自然是"左正"，内部的车体偏航角就是这么取的；而**发回给电控的 `target_yaw` 与第一阶段 UI 上显示的 `pnp_yaw_rad` 都取右正**，两者互为反号，是为了一致性有意这么分的。

**答错的后果**：滤波器跟得住、指令方向反 180 度，而重投影误差、深度这些自检闸门全都看不出来，属于静默错。改法只有两处符号要一起翻，代价很小，但必须先问清楚：如果电控是左正，那我们发回去的 `target_yaw` 也得翻，否则差的是两倍角。

### 1.7 `message.yaw` 是机械角还是场地角

**问**：电控下发的 `yaw` 是"云台相对车体底盘"的机械角，还是已经和 IMU 融合的"相对场地"的角？

**当前默认**：不区分，两种口径下公式都自洽，只影响怎么解释。

**答错的后果**：数值不会错，错的是解释。答辩被问"你这个 yaw 相对谁"答不上来是概念错；另外也决定一帧多车该在哪一层筛。

## 第 2 组：顺带问

### 2.3 弹速

**问**：实际弹速多少？

**当前默认**：24 m/s。这个数我们没选过，是仓库里 `armor/src/BulletModel.cpp:5` 构造函数写死的默认值。同一个仓库里还有另外两个：`armor/include/Planner.hpp:47` 的 23.5 和 `armor/src/Planner.cpp` 越界时回落的 23.0。想请给一个真值，或者告诉我们上车用测速仪量一次也行。

**答错的后果**：弹道飞行时间对初速敏感，远距离提前量直接受影响；下坠补偿量也随初速变，5 m 处 23 / 24 / 25 m/s 分别是 2.69° / 2.47° / 2.27°。

### 2.5 车上那台相机内参的标定材料

**问**：`config/camera.yaml` 现在这组（fx 1782.6 / fy 1784.3 / cx 749.4 / cy 574.7，畸变 `[-0.0357, -0.1533, 0, 0, 1.1905]`）是哪台相机、用什么工具、采了多少张图标的？

**为什么问**：提交物里要一份"完整标定材料"，包含标定方法、采样过程和误差验证。这组数是队里给的，我们手上只有数值本身。如果队里标过，把工具和采图张数给一句就够；有平均重投影误差的话一并给。

### 2.7b 一帧里可能有几辆敌车

**问**：一帧画面里通常有几辆敌车？有可能两辆及以上同框吗？

**为什么问**：培训文档里那条链路写的是「数字识别与**目标筛选**」，筛选是识别阶段的一环。我们现在的流程把一帧里所有同色装甲板全部喂给同一个"单目标四板"模型，EKF 之前没有目标筛选层。若经常两辆同框，八块板会一起进一个模型，要先定筛选放在哪一层；若基本只有一辆，这条可以直接跳过。

## 第 3 组：上车当天我们自己量，不用答

写在这里只是说明我们清楚这几项还空着，不是要你回答：

- 相邻两块装甲板的**高差**：高度表现在按四块共面填。已确认它只影响 `center_z_m` 上报量、不影响瞄准（高度和中心高度进的是同一个方程），所以不专门量；换板时 `ekf_z_m` 的台阶顺带就能读出来
- 装甲板到车体旋转中心的**半径**：现在按 0.273 m 的实测值（2026-10-20 在靶车上量得旋转中心到板心 27.3 cm，相邻板心 38 cm，√2 × 0.273 = 0.386 m 与之一致）
- 车的**机动能力量级**：决定过程噪声大小，要在车上扫参数
- 弹速：若没有人知道真值，上车当天用测速仪量一次
- `7` 号板上的贴纸是不是 `7`：现场看一眼
- 一句范围问题：本轮要不要跟踪**前哨站**，不要的话就按标准步兵四块板做
