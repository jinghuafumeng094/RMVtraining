# 上车前问题清单

面向学长的提问单。分三组：上车前必须落定的（第 1 组）、上车当天现场量的（第 2 组）、收材料时用的（第 3 组）。

每条给出：问什么、为什么问、当前默认值、答错的影响。

---

## 第 1 组：上车前必须问清，不落定就不该上车

### 1.1 外参 `translation_camera_to_gimbal` 的方向符号 —— **已答（2026-10-13）**

**学长答复**：外参是"云台 P 轴到相机光心"。

**结论**：本字段的定义（从云台原点指向相机原点，云台原点取 P 轴）与之同向，所以 handout 那三个数就是本字段的值，不需要取负。`config/camera.yaml` 已改为：

```yaml
data: [ 0.06711, 0.0, 0.0515 ]
```

原先写的是 `(-0.06711, 0, -0.0515)`，多了一次负号。

**剩余**：handout 没写这三个分量在哪个坐标系里量的。`R = I` 时两系同向、不影响；若相机支架确有安装偏角使 `R != I`，需再确认。

### 1.2 `target_yaw` / `target_pitch` 要绝对云台角还是相对角 —— **已答（2026-10-13）**

**学长答复**：target 的解算接口已经给出了，不需要考虑。

**结论**：不自行决定，按给定接口（`PredictionResult` -> `applyPrediction`）实现。现实现输出绝对云台角，与框架 `setSafeOutput()` 写 `target_yaw = message.yaw` 自洽，保持不变，也不加开关。

**备注**：第一阶段 Web Debug 的 `pnp_yaw_rad`（`main.cpp:442`）是**相对角**，与 `target_yaw` 不是同一个量，`main.cpp` 的注释已写明，两者口径本就允许不同。

### 1.3 `crc` 的 0 / 1 / 2 是否就是 NoTarget / Unstable / Stable

**问**：`crc` 三个值的语义确认（本作业里它是 EKF 状态，不是校验和）。

**当前实现**：按 `轨迹预测说明.md:16` 与 `docs/大作业任务书.md:66`：

- `crc = 0` 无目标
- `crc = 1` 预测稳定（唯一可开火）
- `crc = 2` 有目标但未稳定

`AutoAimTypes.hpp` 的 `TrackingState` 枚举数值故意设成 `NoTarget = 0, Stable = 1, Unstable = 2`，`AppSupport.cpp:94` 直接搬运，没有一处算校验和。

**要确认的**：一是这三个值是否与电控侧一致；二是"稳定"的判据由谁定——现在是我实现的 `stable_frames = 15` 帧 + 协方差门 + NIS 均值门，电控是否有自己的期望。

### 1.4 `armor_yaw` 是板面法向方位角，还是板心相对旋转中心的方位角 —— **已答（2026-10-13）**

**学长答复**：与 1.2 同一句，"target 的解算接口已经给出了，不需要考虑"。

**结论**：定义由给定接口决定，不自行改。EKF 本就不使用 `armor_yaw`（只喂板心三维位置），`armor_solve` 保持不变。

**存疑**：若学长那句话只是针对 1.2，则本条仍未答，下次补问一句。

*以下是原始问题的背景，保留备查。*

**问**：任务书里的 `armor_yaw` 指哪个？

**为什么问**：两种解释在"板子正对相机"时都是 0，但侧对时完全不同。

- 板面**法向**的方位角（板子朝哪）：现实现，`StudentTasks.cpp:174` 取板面 +z 轴在云台系的 `atan2(x, z)`。
- 板心相对**旋转中心**的方位角（板子在车身哪个方位）：任务书三处措辞偏向这个。

**影响**：EKF **不用** `armor_yaw` 当观测量（只喂板心三维位置），所以跟踪不受影响。影响面是 Web Debug 的解释、实验报告怎么写、以及第一阶段答辩文档里挂着的"待复核"。若确认是后者，`armor_solve` 里那一行 `atan2` 要改，改动面很小。

### 1.5 `GimbalState::yaw/pitch` 的符号约定

**问**：电控下发的 `gimbal.yaw` 是右正还是左正？`gimbal.pitch` 是抬头正还是低头正？

**当前实现**：`yaw` 右正、`pitch` 上正。因为 `gimbalToWorld` 是唯一一处 G->W 变换，若符号反了，把它换成自身转置即可，只改一处。

**答错的影响**：跟踪位置对、方向错，但重投影误差、深度这些闸门都看不出来（静默错）。会表现为"滤波器跟得住但指令方向反了"。

## 第 2 组：上车当天现场量的

### 2.1 车的机动能力量级

**问**：真车的三轴加速度、yaw 角加速度大概什么量级？

**当前值**：`accel_noise_m_s2 = 6.0`（依据"RM 步兵 0 到 20 m/s 约 1 到 2 秒，瞬时机动约 10 m/s²，取一半"）、`angular_accel_noise_rad_s2 = 12.0`。

**用途**：这两个是过程噪声 Q 的强度，决定滤波器"以为车能多猛"。Q 大则跟得快但抖，Q 小则平滑但滞后。要按博客 §3.7 的顺序，固定 R 再调 Q。

### 2.2 装甲板到旋转中心的半径 `r1` / `r2`

**问**：标准步兵两块板到车体旋转中心的半径大约多少？

**当前值**：初始化假定 `initial_radius_m = 0.25`。标准车两块板同量级（`r1 ≈ r2`）。

**注意**：半径只有在车旋转、且多块板都被看到时才能被观测到。只有 2 块可见而间距仍按 90° 排时，两块会落在同奇偶槽位，`r2` 永远没有观测，报出去的是先验假数。
**2026-10-13 实测补充**：离线跑下来，块数少时问题比"没观测"更严重 —— 初始化会锁死错的槽位编号，
半径跑成负数还报 `Stable`。见 2.7。

### 2.3 弹速与摩擦轮口径方向

**问**：实际弹速多少？摩擦轮 74.1 mm 口径的方向（决定气动模型里哪一侧）？

**当前值**：用仓库默认初速 24 m/s（`armor/include/BulletModel.hpp`，`Kf = 0.08`，`gravity = 9.81`）。

**影响**：弹道飞行时间对初速极敏感，远距离提前量直接受影响。

### 2.4 前哨站是否也要跟踪

**问**：本轮要不要跟踪前哨站？

**当前默认**：按标准步兵 4 块 90° 处理。`Config` 已支持 `plate_count = 3` + `plate_spacing_rad = 120°` + 不共面的 `plate_height_m`（来源 `armor/include/Planner.hpp:60-62` 的 `{0, -0.102, +0.102}`），改配置即可，代码不用动。

### 2.5 上车那台相机的内参 / 畸变

**问**：车上相机的内参与畸变系数。

**为什么必须**：`config/camera.yaml` 现有那份是**本机标定**的，不是车上的。EKF 吃的是 `armor_solve` 输出的板心位置，内参错了位置就错，滤波器会把误差当成目标运动吃进去。

### 2.6 电控下发的 `message.bias`（`prediction_bias_s`）的含义与单位

**问**：`bias` 字段的单位是不是秒？代表什么延迟？

**当前用法**：按秒用，进 `t_pred = latency_s + prediction_bias_s + t_flight`。`latency_s` 是我在 `ekf_predict` 里实测的（`steady_clock` 纪元秒差）。

### 2.7 车上一般同时能看到几块装甲板（2026-10-13 新增）

**问**：实际跑起来，一帧画面里通常检到几块板？一直只有 1 到 2 块，还是经常有 3 到 4 块？

**为什么问**：离线跑 `ekf_trace`（仓库外自测工具，不需要相机）时发现，
**每帧只喂 1 到 2 块板会让滤波器在初始化头 3 帧锁死一个错误的板槽编号**，
然后收敛到错的地方：半径状态跑成负数（`r1 = -0.083`，真值 0.25），
车体 yaw 差 0.79 rad，中心差 0.18 m。**而且它报 `Stable`、拒绝计数为 0**
—— 不是"没收敛"，是"很有信心地收敛到错的解"。

反过来，前面 40 帧凑齐四块板、之后立刻回到真实可见性，就一路精确跟踪，
说明**稳态本身没问题，毛病只在初始化那 3 帧**。

**现成的测试为什么没发现**：`tests/test_ekf_predict.cpp:73` 每帧发全部四块板，
正好绕开了这个分支。

**若确实经常只有 1 到 2 块**，需要改初始化逻辑（三个方向，还没定）：
要求建滤波器时至少两块板同时可见且夹角与 `plate_spacing_rad` 自洽；
或给 `r1`/`r2` 加非负约束；或用板上读到的数字做关联线索。

**证据**：`rm_autoaim_evidence/06-EKF跟踪与预测/20261013-ekf_trace-离线状态机与初始化分支.md`。
**当前状态**：未改实现，等这个问题有答案再定。
