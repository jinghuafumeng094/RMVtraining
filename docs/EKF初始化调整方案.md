# EKF 初始化调整方案

日期：2026-10-13
适用：`student/src/ArmorEkf.cpp:336-343` 的初始化段
前一版结论：`docs/上车前问题清单.md` §2.7、`rm_autoaim_evidence/06-EKF跟踪与预测/20261013-ekf-fix-trials-候选修法全试过.md`

**一句话**：初始化的方位角方向取反了 180°。代码假设观测到的板**背对**相机，
而能被检出的板必然**面朝**相机。改一行（`atan2(y,x)` 换成 `atan2(-y,-x)`）之后，
实测初始中心误差 0.50 m 变 0.02 m、收敛后 0.188 m 变 0.003 m，
半径从负数回到 0.248/0.252，而且不再 21 帧就报 `Stable`。

**本文件只给方案，`ArmorEkf.cpp` 一个字没动。**

---

## 一、根因

初始化段（`ArmorEkf.cpp:336-343`）把**板心相对世界原点**的方位角，
当成了**板心相对旋转中心**的方位角：

```cpp
x_[Yaw] = wrapToPi(std::atan2(init_mean_.y(), init_mean_.x()));
x_[Px] = init_mean_.x() - config_.initial_radius_m * std::cos(x_[Yaw]);
x_[Py] = init_mean_.y() - config_.initial_radius_m * std::sin(x_[Yaw]);
```

`x_[Yaw]` 这个量在模型里的含义是槽位 0 的 `psi`，也就是**中心指向板心的径向方位**。
代码给它的取值是**原点指向板心的视线方位**。两者只有在车心恰在世界原点时才相等。

换成向量的说法更清楚。记

- `r_hat`：中心指向板心的单位径向（板装在外侧，板面法向就是它）
- `p_hat`：原点（相机）指向板心的单位视线
- `delta`：`r_hat` 与 `-p_hat` 的夹角，也就是这块板被看到的**斜角**

代码隐含假设 `r_hat = p_hat`。但检测条件是"板面法向与指向相机的方向夹角小于锥角"，
即 `angle(r_hat, -p_hat) = delta < 锥角`，所以真实关系是 **`r_hat` 约等于 `-p_hat`**。
假设方向整整反了 180°。

初始中心误差就是两个假设向量之差乘以半径：

| 假设 | 中心误差 | `delta` 在可见范围 `[0°, 80°)` 内的取值 |
|---|---|---|
| 现状 `r_hat = p_hat` | `2r·cos(delta/2)` | `(0.383, 0.50]` m |
| 取反 `r_hat = -p_hat` | `2r·sin(delta/2)` | `[0, 0.321)` m |

取 `r = 0.25` m。正对相机时 `delta = 0`：现状偏 0.50 m，取反偏 0；
掠射到锥角边缘 `delta = 80°`：现状偏 0.383 m，取反偏 0.321 m。
在 `delta < 90°` 的整个范围内 `sin(delta/2) < cos(delta/2)`，
所以**凡是能被检出的姿态，取反都严格优于现状**。这不是调参，是把一个符号改回来。

（`delta > 90°` 也就是板在车的远侧、面朝外背离相机的那半边，现状反而是对的。
但那半边根本检不出来，实车数据里不会出现。测试夹具里会出现，见第四节。）

## 二、实测

工具：`testrig/ekf_trace`（合成旋转车体，真值中心 (5.0, 0.0)、速度 (0.3, 0.6) m/s、
自转 2.0 rad/s、半径 0.25 m、165 fps、云台 yaw 固定 0、锥角 80°）。
变体源码 `/tmp/rm_ekf_fix/ArmorEkf_G.cpp`，与 base 的差别只有一行：

```
-x_[Yaw] = wrapToPi(std::atan2(init_mean_.y(), init_mean_.x()));
+x_[Yaw] = wrapToPi(std::atan2(-init_mean_.y(), -init_mean_.x()));
```

原始输出 `var_base_direct.txt` / `var_G_direct.txt`，已复制到
`rm_autoaim_evidence/06-EKF跟踪与预测/20261013-初始化方位角取反/`。

| | frame 7（t=0.042） | frame 120（t=0.727） | frame 189（t=1.145） |
|---|---|---|---|
| 真值中心 | (5.013, 0.025) | (5.218, 0.436) | (5.344, 0.687) |
| 现状中心 | (4.512, 0.003) 错 0.501 m | (5.075, 0.326) 错 0.180 m | (5.327, 0.500) 错 0.188 m |
| 取反中心 | (5.012, 0.004) 错 0.021 m | (5.233, 0.416) 错 0.025 m | **(5.344, 0.690) 错 0.003 m** |
| 现状半径 | (0.250, 0.250) | 内部 (−0.083, 0.177) | 内部 (−0.083, 0.175) |
| 取反半径 | (0.250, 0.250) | (0.232, 0.267) | **(0.248, 0.252)** |

- 初始那一帧就对了：frame 7 误差 0.021 m 对现状的 0.501 m，正好是 2r 的量级。
- 半径全程不再出现负值。现状的 `r1 = -0.083` 是错解的指纹。
- 速度、角速度（取反 `w = 1.988` 对真值 2.0）都收敛。
- **转入 `Stable` 的帧号：现状 21、取反 164。** 现状是在错 0.5 m 的状态上报的 Stable。

对照：`rm_autoaim_evidence/.../20261013-armor_yaw定中心...md` 里，
用**真值** `armor_yaw` 定中心的 F 变体在 frame 189 的误差是 0.001 m。
取反的 0.003 m 与它同量级，**而且不需要 `armor_yaw`**。

## 三、为什么前面三份证据没到这一层

前面把根因归到"半径自由度"再归到"初始化窗口"，那一层是**下游**：
初始化偏了，滤波器才挪用半径去拟合。这一层是初始化的**输入方向**本身错了。

`ekf_trace` 的合成观测由 `ArmorEkf::observationModel` 生成，
只喂**可见的那些板**（`visiblePlates`，锥角 80°），与真实检测口径一致，
所以它能复现。而下面的测试夹具口径不一致，所以它复现不出来。

---

## 四、配套必改：测试夹具（这次调整里工作量最大的一块）

`tests/test_ekf_predict.cpp:70` 的 `feedFrame` **无条件**发 `plate_count` 块板：

```cpp
for (int index = 0; index < config.plate_count; ++index) {   // :73
    const Eigen::Vector3d z = to_gimbal * truePlateWorld(truth, index, config);
    ...
    observation.armor_yaw = 0.0;                             // :78
```

对一辆四板车、车心在 (4, 0.3, 0.6) m，这等于每帧发两块**背对相机**的板。
真实检测器永远不会输出这种配置。夹具把错误方向当成了正确方向，
这正是这条 bug 能在测试全绿的情况下活下来的原因。

已实测的连带影响（不是猜）：

- **`testNoiselessConvergence`**：把夹具改成"只发可见板"后，base 与取反**都**不再满足
  `1e-6` 的严格断言（也都在预算内转不了 Stable）。这条用例的观测数变少，
  帧数预算要重新定。
- **`testTwoPlateVehicleObservesRadiusTwo`**：板间夹角是 `pi`，两块板对置。
  在可见性约束下，**任何时刻两块板里只有一块能看见**（`psi` 与 `psi+180` 的可见区间不相交），
  于是这条用例退化成"永远单板"。它现在断言的 `yaw 误差 < 5e-3`、`r1-r2 < 0.04`
  在单板轮换观测下**是否可辨识，需要先定**，不能直接沿用。这条要整体重写。

也就是说：取反这一行本身是确定收益的，但**测试要跟着重做**，
而重做之后的断言强度会变（观测少了）。这块我没做完，是本方案唯一的开口。

## 五、第二层：可观测性门（独立，建议保留）

理由与取反正交：取反修的是"初始化偏在哪个方向"，
它不改变"只看见一块板时旋转中心根本不可观测"这件事。
取反在这条轨迹上之所以晚报 Stable，是因为误差小、协方差收得慢，
属于**涌现行为，不是保证**。换一条轨迹（比如卡在锥角边缘的掠射姿态）就可能又 21 帧报 Stable。

做法：在 `advanceStateMachine`（`ArmorEkf.cpp:444`）的 Unstable 转 Stable 条件里加一条

```
去过偶数槽位的观测 && 去过奇数槽位的观测
```

- 用**槽位奇偶**而不是"见过几块板"，因为 `radiusIndex`（`:112`）按奇偶分 `r1`/`r2`：
  两块相差 180° 的板落在**同奇偶**槽位，打破不了半径简并，只数块数是错的。
- 判据只在"观测被接受"时置位（过了三道闸的才算）。
- 代价：两板对置的车永远满足不了这条 → 永远不许开火。
  是否要放宽（例如 `omega` 被稳健估成 0 时放行）需要先定，这是第二节那个未闭环问题的同一件事。

---

## 六、不做

- **无条件用 `armor_yaw` 定中心**：真帧上平板 PnP 双解的方位角中位差 52°、最大 100°，
  扫 `Delta` 的结果是 `Delta = 45°/100°` 比现状更差。取反已经把这块收益吃掉了，不需要它。
- **约束半径**（非负夹、夹区间、两半径合成一个状态）：前面全试过，一个都没把中心拉回真值。
- **动 `P0` / `Q` / `R`**：这次改的是初始化的输入方向，不是噪声谱。

---

## 七、顺序

1. 改 `ArmorEkf.cpp:338` 一行（取反）。
2. 改夹具：`feedFrame` 加可见性筛选（与 `ekf_trace` 同一条锥角判据）。
3. 重定 `testNoiselessConvergence` 的帧数预算；重写 `testTwoPlateVehicleObservesRadiusTwo`。
4. 新增一条"少板初始化"回归用例，直接把这次的 bug 钉住：
   单板/双板可见时，初始化后的中心误差要小于一个由 `2r` 定的界，**且一块板时不许报 Stable**。
5. 加可观测性门（可与 1 独立提交，便于单独回退）。
6. `ctest` 全绿之后再上车。

## 八、未闭环

- 两板对置车在可见性约束下的可观测性结论（决定第四节那条用例怎么写，也决定第五节的门要不要放宽）。
- 取反在**真实观测流**上能否复现。`ekf_trace` 是合成观测，只验了机制；
  真帧要等上车，或用仓库里那 69 张整图搭一条离线观测流。
- `tests/test_ekf_predict.cpp:78` 的 `armor_yaw = 0.0` 是占位值，
  取反不读这个字段，所以这次可以不动；将来若走 `armor_yaw` 那条路必须同改。

## 九、复现

```bash
cd /tmp/rm_ekf_fix
echo 'x_[Yaw] = wrapToPi(std::atan2(-init_mean_.y(), -init_mean_.x()));'   # 取反那一行
bash build.sh ArmorEkf_base.cpp ekf_base ekf_trace.cpp
bash build.sh ArmorEkf_G.cpp    ekf_G    ekf_trace.cpp
./ekf_base --direct > var_base_direct.txt
./ekf_G    --direct > var_G_direct.txt
```

`--direct` 才打内部 `x_`，负半径只在内部看得见（`:677-678` 上报前已经 `std::max(0.0, ...)`）。
没有 `--fast`：必须真睡够帧间隔，否则 `ekf_predict` 内部量到的 latency 会被截到 0.2 s。
